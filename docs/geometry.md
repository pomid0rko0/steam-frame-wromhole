# Геометрия и метод

## Пространство

Червоточина из видео optozorax — трёхмерная поверхность в плоском четырёхмерном пространстве R⁴ с координатами x, y, z, w. Видео задаёт её 4D SDF — функцией расстояния со знаком:

```
union_round(плоскости w = ±h, extrude_w(сфера ρ₀, h), R)
```

Два плоских мира — гиперплоскости w = +h (мир A) и w = −h (мир B). Их соединяет сфера радиуса ρ₀, вытянутая вдоль оси w от одного мира до другого; места соединения скруглены радиусом R. В видео ρ₀ = 0,3, h = 0,5, R = 0,1; здесь 1 единица = 10 м: горло радиусом 3 м, миры в 10 м друг от друга, скругление 1 м. Прямой участок горла (цилиндр) — 8 м по оси w; скругления занимают по 1 м по оси w с каждой стороны, а вдоль самой поверхности — по 1,57 м (L = 5,57 м).

Поверхность сферически симметрична, поэтому её метрика выписывается точно:

```
ds² = dl² + r(l)² dΩ²
цилиндр    |l| ≤ Lc:       r = ρ₀                     w = l
скругление Lc ≤ |l| ≤ L:   r = ρ₀ + R(1 − cos θ)      w = ±(h − R + R sin θ),   θ = θ₀ + (|l| − Lc)/R
плоско     |l| ≥ L:        r = |l| − L + Rout         w = ±h
Lc = max(h − R, 0),   θ₀ = asin(max(1 − h/R, 0)),   L = Lc + R(π/2 − θ₀),   Rout = ρ₀ + R
```

l — расстояние вдоль поверхности от середины горла (l > 0 в мире A, l < 0 в мире B), r(l) — радиус сферы на этом расстоянии. Мир трёхмерный: ось w нужна только чтобы задать его форму, ходить и светить можно лишь по самой поверхности.

| | |
|---|---|
| точка | (l, n): l и единичный вектор n — направление от центра червоточины |
| направление | (U_l, u): составляющая вдоль l и поперечная часть, u ⊥ n |
| в R⁴ | (r(l) n, w(l)) |
| плоские координаты мира | в A x = r(l) n, в B то же с отражённой осью x |
| кривая зона | \|l\| < L: горло (цилиндр, \|l\| ≤ Lc) и два скругления; снаружи миры плоские |
| r_min | самый узкий радиус горла: ρ₀, если цилиндр есть |
| пол | поверхность n_z = 0 |

Пол вполне геодезический (геодезическая, начатая вдоль него, на нём и остаётся), поэтому продолжается сквозь горло: по нему можно пройти из мира A в мир B.

**Связь с ОТО.** Если добавить время без замедления часов, получится статическое пространство-время `−dt² + ds²` — червоточина Морриса–Торна с нулевой функцией красного смещения. Свет в нём в проекции на пространство идёт ровно по геодезическим `ds²`, так что картинка точна и для этой червоточины ОТО. Видео приближает те же геодезические шагами «шаг вперёд + проекция на поверхность»; здесь они считаются без шагов, с ошибкой из раздела «Точность».

**Длина горла.** При постоянном скруглении R:
- **h < R** — цилиндра нет, скругления сходятся изломом, у r(l) острый минимум, круговой орбиты света нет: червоточина похожа на линзу, повторов миров нет;
- **h = R** — минимум r(l) становится гладким: появляется фотонная сфера, лучи у неё огибают горло много раз, миры повторяются;
- **h > R** — между скруглениями цилиндр длиной 2(h − R) (здесь 8 м), и свет может обходить горло по кругу на всей его длине.

## Почему луч считается быстро

1. **Луч лежит в плоскости через центр** — следствие сохранения момента импульса. Момент луча — прицельный параметр b, а угол, на который луч поворачивается в своей плоскости, — один интеграл `ψ = ∫ b dl / (r √(r² − b²))`.
2. **На цилиндре** интеграл берётся формулой.
3. **На скруглении — без шагов.** В переменной `u = sin²(θ/2)` угол равен `∫ F(u) dv` с гладкой F. Вся трудность собрана в весе `dv = du / (2√(u(u − σ)))`, `σ = (b − ρ₀)/2R`: корень в точке поворота луча и логарифм при b → r_min, из-за которого лучи у фотонной сферы много раз огибают горло.

   Поэтому F заменяется многочленом по четырём точкам, а интегралы от степеней u с этим весом берутся в замкнутом виде (product integration). Интеграл до любой точки пути считается той же формулой, и точка, где луч падает на пол, находится двумя шагами Ньютона.
4. **Коэффициенты многочлена зависят только от b**, поэтому шейдер берёт их из таблицы (`WormholeSpace.fillet_table`, 4 строки по 256 значений b), а видеокарта интерполирует между значениями. У края кривой зоны коэффициенты уходят в ноль как корень, и линейная интерполяция такое теряет; поэтому этот множитель из таблицы вынесен, и пиксель возвращает его сам. Таблица строится при старте.
5. **Вне кривой зоны лучи прямые**, и предметы там пересекаются с лучом формулами.
6. **Пол в кривой зоне ищется не для всех лучей.** На луче n_z меняется как синус угла в его плоскости, начинается с плюса и проходит ноль через каждые π. Значит, луч доходит до пола внутри кривой зоны, только если поворачивает на π и больше или выходит из неё с n_z < 0; угол точки пола и шаги Ньютона считаются только для таких лучей.
7. **Длину пути в кривой зоне** (её берут дымка, толщина рёбер кубов, стрелки и шаг поиска предметов) шейдер берёт оценкой `r²/b · ψ`, без отдельного интеграла: так ему нужно меньше регистров.

В шейдере это `godot/shaders/wormhole_core.gdshaderinc`.

## Точность

`ref/wh.py` повторяет метод шейдера во float64 (коэффициенты — для каждого луча, без таблицы; длина пути — точно, без оценки), а `ref/test_fast.py` сверяет его с прямым интегрированием геодезической (метод Рунге–Кутты, RK4) на пяти формах горла — из видео, h = R, излом h < R, тонкое скругление, длинное скругление — по 240 лучей на форму:
- что луч встречает (пол, выход из кривой зоны, проход сквозь горло) совпадает везде;
- для горла из видео точка выхода из кривой зоны отличается не больше чем на 6,6·10⁻⁵ ρ₀ (0,2 мм), направление — на 2,4·10⁻⁵ рад (0,0014°), точка на полу — на 5,8·10⁻⁵ ρ₀;
- точка выхода и направление хуже всего на изломе (7,5·10⁻⁴ ρ₀ и 4,5·10⁻⁴ рад), точка на полу — на длинном скруглении (5,5·10⁻⁴ ρ₀).

Порогов у `test_fast.py` нет: это вывод прогона с фиксированным набором лучей.

Сам шейдер во float32 против этого эталона сверяет `ref/test_gpu.py`.
