# Геометрия и метод

## Пространство

Червоточина из видео optozorax — трёхмерная поверхность в плоском четырёхмерном пространстве R⁴ с координатами x, y, z, w. Видео задаёт её 4D SDF — функцией расстояния со знаком:

```
union_round(плоскости w = ±h, extrude_w(сфера ρ₀, h), R)
```

Два плоских мира — гиперплоскости w = +h (мир A) и w = −h (мир B). Их соединяет сфера радиуса ρ₀, вытянутая вдоль оси w от одного мира до другого; места соединения скруглены радиусом R. В видео ρ₀ = 0,3, h = 0,5, R = 0,1; здесь 1 единица = 10 м. Прямой участок горла (цилиндр) — 8 м по оси w; скругления занимают по 1 м по оси w с каждой стороны, а вдоль самой поверхности — по 1,57 м (L = 5,57 м).

Поверхность сферически симметрична, поэтому её метрика выписывается точно:

```
ds² = dl² + r(l)² dΩ²
цилиндр    |l| ≤ Lc:       r = ρ₀                     w = l
скругление Lc ≤ |l| ≤ L:   r = ρ₀ + R(1 − cos θ)      w = ±(h − R + R sin θ),   θ = θ₀ + (|l| − Lc)/R
плоско     |l| ≥ L:        r = |l| − L + Rout         w = ±h
Lc = max(h − R, 0),   θ₀ = asin(max(1 − h/R, 0)),   L = Lc + R(π/2 − θ₀),   Rout = ρ₀ + R
```

l — расстояние вдоль поверхности от середины горла (l > 0 в мире A, l < 0 в мире B), r(l) — радиус сферы на этом расстоянии, единичный вектор n — направление от центра червоточины; точка пространства — (l, n). Мир трёхмерный: ось w нужна только чтобы задать его форму, ходить и светить можно лишь по самой поверхности. Кривая зона — |l| < L (горло и два скругления), снаружи миры плоские; r_min — самый узкий радиус горла.

Пол — поверхность n_z = 0. Он есть при любом l и проходит сквозь горло: по нему можно пройти из мира A в мир B. Он вполне геодезический: геодезическая, начатая вдоль него, на нём и остаётся.

**Связь с ОТО.** Если добавить время без замедления часов, получится статическое пространство-время `−dt² + ds²` — червоточина Морриса–Торна с нулевой функцией красного смещения. Свет в нём в проекции на пространство идёт ровно по геодезическим `ds²`, так что картинка точна и для этой червоточины ОТО. Видео приближает те же геодезические шагами «шаг вперёд + проекция на поверхность»; здесь они считаются без шагов (раздел «Картинка»), с ошибкой из раздела «Точность».

**Длина горла.** При постоянном скруглении R (рендер — только h ≥ R):
- **h < R** — цилиндра нет, скругления сходятся изломом, у r(l) острый минимум, круговой орбиты света нет, и наибольший поворот луча конечен: чем острее излом, тем он меньше; при h → R он растёт без предела, так что у почти гладкого излома миры ещё повторяются;
- **h = R** — минимум r(l) становится гладким: появляется фотонная сфера, лучи у неё огибают горло много раз, миры повторяются;
- **h > R** — между скруглениями цилиндр длиной 2(h − R), и свет может обходить горло по кругу на всей его длине.

**Движение наблюдателя и предметов** — геодезические с параллельным переносом. Вектор в точке (l, n) — пара (U_l, u): составляющая вдоль l и поперечная часть, u ⊥ n. Для скорости V = (V_l, v) и для каждого переносимого вектора U:

```
dl/ds = V_l,   dn/ds = v / r,   dU_l/ds = (r'/r) v·u,   du/ds = −(r'/r) U_l v − (u·v / r) n
```

## Картинка

Рендер (`godot/renderer.gd`) делит кадр на две части, и каждая стоит дёшево там, где дорого было бы другое:

- **Тела** (мячи, кубы, шары рук, неподвижные предметы) — сетки, которые растеризует сам GPU. Каждую вершину шейдер ставит туда, где её видит глаз: находит направление из глаза, чья геодезическая доходит до вершины, и длину этой геодезической. Это нормальные координаты глаза: лучи глаза в них прямые, поэтому обычная растеризация рисует то, что видит глаз, — точно в вершинах, а между ними сетка достаточно мелкая. Глубина — длина пути, тела закрывают друг друга как надо. Тело стоит по вершинам, а пиксель тела — только раскраска: куб на весь вид у самых глаз дешевле пола, который он закрывает.
- **Пол и небо** — четырёхугольник на весь вид на дальней плоскости, рисуется после тел; тест глубины пропускает только пиксели, где тела нет. Луч пикселя доходит до пола или неба по таблицам и формулам ниже, за одну и ту же цену при любом виде.

**Каждую точку глаз видит не больше одного раза.** Геодезическая из глаза лежит в плоскости через центр: её направление n(φ) идёт по большому кругу, φ — поворот луча. Пол — n_z = 0 при любом l, и большой круг пересекает экватор раньше, чем повернёт на π: луч, повернувший на π, уже упал на пол. Значит, видимая точка над полом достижима только по меньшей дуге между направлениями глаза и точки, а меньшая дуга между двумя точками над экватором вся над ним — **пол не закрывает ни одного тела**. Вдоль меньшей дуги поворот растёт монотонно, пока r(l) выпукла на каждой стороне (r″ ≥ 0; у этого профиля так): лучи, проходящие сквозь горло, поворачивают тем больше, чем ближе прицельный параметр b к ρ₀, а лучи одной стороны, сначала идущие от горла, а затем огибающие его, — тем больше, чем сильнее огибают. Поэтому у каждой точки одно изображение, тело рисуется один раз, а отображение «точка → место на экране» гладкое везде, кроме полос вдоль края горла, где поворот резко растёт (там сетки мельче: `Renderer._detail`).

**Луч.** Момент сохраняется, b = r sin(угол к радиусу). Поворот на цилиндре — `b Δl / (ρ₀ √(ρ₀² − b²))`, в плоских мирах луч прямой. На скруглении — в переменной s = sin(θ/2), r = ρ₀ + 2R s², σ = (b − ρ₀)/2R:

```
s = c sh y   (σ < 0, луч проходит горло)      s = c ch y   (σ ≥ 0, луч поворачивает в точке y = 0)      c = √|σ|
dφ = A dy,   A = b √(2R) / (r √(r + b) √(1 − s²))           dпуть = √(2R) r / (√(r + b) √(1 − s²)) dy
```

Обе подынтегральные функции гладкие и ограниченные: корень в точке поворота и логарифм у фотонного цилиндра (b → ρ₀, лучи огибают горло много раз) ушли в замену. Отсчитанная от внешнего края скругления, z = Y − y, точка луча — `s(z) = s₁ ch z − k sh z`, k = √(½ − σ), s₁ = sin 45°: это аналитическая функция σ, без особенности при b = ρ₀. Поворот от внешнего края на z — `A₀ z + E(b, z)`, путь — `P₀ z + F(b, z)`, A₀ и P₀ — значения подынтегральных функций при s = 0, а E и F — таблицы 256 × 64 (`WormholeSpace.shader_tables`): столбцы по b через корень из |b − ρ₀|, узлы по z = 6 v², между узлами — кубический Эрмит по значениям и наклонам. Поворот между двумя точками одного луча — разность таких значений; ноги луча (скругление внутрь, цилиндр, скругление наружу) складываются только там, где луч идёт, — никогда разности больших чисел.

**Пиксель.** Поворот до пола известен сразу: `φ_пол = atan2(n_z, −t_z)`, t — направление луча вдоль большого круга. Если до выхода из кривой зоны луч повернёт меньше, пол в ней: точку, где поворот равен φ_пол, находят тремя шагами Ньютона по таблице (производная — сама A). Иначе луч выходит в плоский мир по прямой — на пол или в небо.

**Вершина.** Направление из глаза на точку — решение «поворот луча от глаза до точки равен углу между ними» относительно b. Ветвей три: луч сквозь горло (b < ρ₀), прямой луч одной стороны и огибающий горло; ветвь выбирают по повороту луча, касающегося ближней из двух точек. На каждой ветви поворот монотонен, и решение ищется Ньютоном в переменной, в которой он почти линеен (`sp_toward`): обычно хватает двух–четырёх шагов. Глаз — геодезическая от головы до него (несколько сантиметров) двумя шагами Рунге–Кутты, с переносом осей комнаты (`sp_walk`).

Всё это — `godot/shaders/space.gdshaderinc`; форма горла там — h ≥ R (цилиндр между скруглениями, может быть нулевой длины).

## Точность

`ref/space.py` считает то же во float64 без таблиц и шорткатов — интегралы адаптивными квадратурами, корни делением отрезка — и сверен с прямым интегрированием геодезической шагами Рунге–Кутты (`brute`). `ref/test_space_gpu.py` гоняет сам шейдер во float32 на GPU (в облаке llvmpipe) против `ref/space.py` на случайных глазах во всех частях пространства; при 4000 случаях:

| | медиана | худшее |
|---|---|---|
| пол или небо пикселя: ошибка, видимая из глаза | 2,4·10⁻⁷ рад | 1,2·10⁻⁴ рад |
| направление на вершину (в 5–60 см от глаза — тоже) | 4·10⁻⁷ рад | 3·10⁻⁵ рад |
| длина пути до вершины | | 0,6 мм |
| глаз от головы: место и оси | 4·10⁻⁷ | 3·10⁻⁶ |

Пиксель шлема — около 10⁻³ рад. Худшие ошибки пола — у лучей, почти касающихся цилиндра горла, где пол растянут на много пикселей; точки пола дальше 100 м (у горизонта, ошибки float32 там видны, но меньше пикселя по цвету) из сравнения исключены. Пороги — в начале `ref/test_space_gpu.py`.
