# Червоточина в VR на Steam Frame

![Червоточина с места старта: пол в клетку, мячи и кубы, сквозь горло виден мир B](docs/images/start.jpg)

Сферическая червоточина в реальном времени на автономном VR-шлеме Valve Steam Frame (GPU Adreno 750). Каждый пиксель каждого глаза — луч света, который идёт по геодезической искривлённого пространства. Через червоточину можно пройти в другой мир, бросить в неё мяч и посмотреть, как сквозь неё проходит гравитация.

Это червоточина из видео optozorax [«Как визуализировать червоточины?»](https://www.youtube.com/watch?v=4oIUKld4WFg) и его проекта [portal](https://github.com/optozorax/portal): трёхмерное пространство, заданное как поверхность в четырёхмерном. В видео луч идёт по этой поверхности мелкими шагами. Здесь используется то, что пространство сферически симметрично: путь луча сводится к одному интегралу, и шейдер берёт его без шагов, сразу для всего пути.

Godot 4.7.2, OpenXR, рендерер Mobile, сборка под Linux arm64.

## Что есть

- **Червоточина из видео:** горло радиусом 3 м, миры в 10 м друг от друга по четвёртой оси, скругление 1 м. Шейдер сверяется с эталоном во float64 попиксельно. → [docs/geometry.md](docs/geometry.md)
- **Стерео.** Луч каждого глаза начинается в самом глазу. Тест рисует одни и те же предметы трассировщиком и самим Godot и требует, чтобы в каждом глазу центры их силуэтов совпали до 0,5 пикселя, а линии сцены проверки — до 2 пикселей. → [docs/rendering.md](docs/rendering.md), [docs/checks.md](docs/checks.md)
- **Мячи и кубы** — тела в кривом пространстве: катятся сквозь горло в другой мир, сталкиваются, отскакивают. → [docs/physics.md](docs/physics.md)
- **Гравитация через червоточину:** потенциал — решение уравнения Лапласа на самом пространстве, и в середине горла сила тяжести впятеро слабее. Её можно показать цветом пола и стрелками. → [docs/physics.md](docs/physics.md)
- **Руки:** grip берёт мяч или куб; отпущенный предмет летит со скоростью руки, куб — ещё и с её вращением. → [docs/physics.md](docs/physics.md)
- **Фовеальный рендеринг:** края картинки считаются грубее, резкая зона следует за взглядом. → [docs/rendering.md](docs/rendering.md)
- **Меню:** частота экрана 72–144 Гц, разрешение, фовеация, показ гравитации; замер скорости сам обходит позы и сравнивает варианты шейдера. → [docs/menu.md](docs/menu.md)

## Управление

| | контроллеры | клавиатура и мышь |
|---|---|---|
| смотреть | головой | мышью (щелчок захватывает её, Esc отпускает) |
| идти / бежать | левый стик / + левый курок | WASD / + Shift |
| поворот | правый стик влево-вправо | Q / E |
| поворот плавный или рывком на 30° | нажать на правый стик | Tab |
| назад к началу, предметы на места | A | R |
| взять / бросить | зажать / отпустить grip | — |
| новый мяч в правую руку | B | — |
| новый куб в левую руку | крестовина вниз | — |
| показ гравитации: пол, стрелки, выкл | крестовина вверх, влево или вправо | G |
| открыть / закрыть меню | Menu на правом, View на левом или нажать на левый стик | M |
| в меню: строка, значение / применить / закрыть | крестовина или левый стик / A / B | стрелки / Enter / Backspace |

На контроллерах без крестовины её заменяют X (вниз) и Y (вверх, влево, вправо). Пока меню открыто, левый стик, крестовина, A и B работают только в нём.

## Запуск

Без шлема, на компьютере с Godot 4.7.2:

```
godot --path godot --xr-mode off
```

Для шлема:

```
tools/setup.sh      # Godot 4.7.2, шаблоны экспорта и всё для проверок
tools/export.sh     # сборка: godot/build/wormhole_vr_<ветка>_steam_frame.zip
```

Как поставить сборку в шлем и забрать оттуда логи — [docs/steam-frame.md](docs/steam-frame.md).

## Проверки

Всё, кроме скорости и проверки одним глазом, проверяется без шлема и без GPU: Vulkan программный, OpenXR даёт Monado, шейдер компилирует компилятор Adreno из Mesa.

```
tools/test_stereo.sh    # стерео: каждый глаз против того, что рисует сам Godot
tools/test.sh           # тесты в Godot: ходьба, меню, руки, физика, гравитация, замер скорости
tools/test_openxr.sh    # приложение через OpenXR
python3 ref/test_gpu.py # шейдер против эталона во float64
```

Что именно они проверяют и с какой точностью — [docs/checks.md](docs/checks.md).

## Устройство

```
godot/
  main.gd             сцена и зритель: ноги на полу, оси комнаты, голова; ходьба и поворот
  tracer.gd           трассировщик: экранный квад, выбор шейдера, униформы, предметы, трафарет
  shaders/            шейдеры трассировщика: ядро (wormhole_core.gdshaderinc), лучи глаз, варианты
  wormhole_space.gd   геометрия на CPU: геодезические, перенос осей, гравитация, таблицы для шейдера
  scene.json          неподвижные предметы: одна сцена для шейдера, физики и тестов
  toys.gd, ball_world.gd, hands.gd                    мячи и кубы, их физика, руки
  foveation.gd, split_pass.gd                         фовеальный рендеринг
  menu.gd, frame_rate.gd, rate_meter.gd, bench.gd     меню, частота кадров, замер скорости
  check_scene.gd      сцена проверки стерео
  tests/              тесты в Godot
ref/                  эталон во float64 и тесты точности
tools/                установка, тесты, сборка, установка в шлем, модель цены кадра
docs/                 как всё устроено
CLAUDE.md             правила для ИИ-агента, который пишет код
```

## Ограничения

- Метод держится на сферической симметрии: тор или произвольная форма потребуют вести каждый луч шагами.
- Освещение своё в каждом мире, теней нет.
