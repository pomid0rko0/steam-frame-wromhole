# Червоточина в VR на Steam Frame

Сферическая червоточина в реальном времени, в стерео и автономно — на мобильном GPU шлема Valve Steam Frame (Adreno 750), без компьютера. Каждый пиксель каждого глаза — луч света, который идёт по точной геодезической искривлённого пространства. Через червоточину можно пройти, бросить в неё мяч и посмотреть, как сквозь неё проходит гравитация.

Проект вырос из видео optozorax [«Как визуализировать червоточины?»](https://www.youtube.com/watch?v=4oIUKld4WFg) и его проекта [portal](https://github.com/optozorax/portal). В видео луч идёт по поверхности мелкими шагами, и 10 секунд анимации считались больше 50 часов. Здесь та же червоточина считается точно и быстро: она сферически симметрична, поэтому путь каждого луча сводится к одному интегралу, и шейдер берёт его без шагов — на цилиндре горла формулой, на скруглении многочленом с точным весом.

Godot 4.7.2, OpenXR, рендерер Mobile, сборка под Linux arm64.

## Что умеет

- **Точная червоточина.** Пространство — гиперповерхность из 4D SDF видео (горло радиусом 3 м и длиной 10 м, скругление 1 м). Её метрика выписана точно, путь луча считается без шагов и расходится с прямым интегрированием геодезической на ~0,001°. → [docs/geometry.md](docs/geometry.md)
- **Стерео без расхождения глаз.** Луч каждого глаза начинается в самом глазу и переносится в кривое пространство геодезической от головы. Тест сверяет каждый глаз с геометрией, которую рисует сам Godot: расхождение — 0,01 пикселя. → [docs/rendering.md](docs/rendering.md)
- **Мячи и кубы с физикой в кривом пространстве.** Они катятся сквозь горло в другой мир, сталкиваются и отскакивают. Рисует их тот же трассировщик, буфер трафарета пускает его дорогой вариант только туда, где предмет может быть виден. → [docs/physics.md](docs/physics.md), [docs/rendering.md](docs/rendering.md)
- **Гравитация через червоточину.** Потенциал — решение уравнения Лапласа на самом пространстве: в горле сила тяжести в пять раз слабее, и мяч там падает как в замедленной съёмке. Поле можно показать цветом пола и стрелками. → [docs/physics.md](docs/physics.md)
- **Руки.** Grip берёт мяч или куб, отпущенный летит со скоростью и вращением руки — и в горле тоже. → [docs/physics.md](docs/physics.md)
- **Фовеальный рендеринг по взгляду.** Края картинки считаются грубее, резкая зона следует за глазами; своя карта плотности по умолчанию считает треть лучей. → [docs/rendering.md](docs/rendering.md)
- **Частота кадров.** Частота экрана меряется по времени кадров OpenXR (SteamVR на Фрейме сообщает её неверно) и переключается из меню; замер скорости сам проходит позы и сравнивает варианты трассировщика. → [docs/steam-frame.md](docs/steam-frame.md)

## Управление

| | контроллеры | клавиатура |
|---|---|---|
| идти / бежать | левый стик / + левый курок | WASD / + Shift |
| поворот | правый стик влево-вправо | Q / E |
| плавный поворот ↔ рывком на 30° | нажать на правый стик | Tab |
| назад к началу, предметы на места | A | R |
| взять / бросить | зажать / отпустить grip | — |
| новый мяч в правую руку | B | — |
| новый куб в левую руку | крестовина вниз | — |
| показ гравитации: пол, стрелки, выкл | крестовина вверх, влево или вправо | G |
| открыть / закрыть меню | Menu на правом, View на левом или нажать на левый стик | M |
| в меню: строка, значение / применить / закрыть | крестовина или левый стик / A / B | стрелки / Enter / Backspace |

На контроллерах без крестовины её заменяют X (вниз) и Y (вверх, влево, вправо). Пока меню открыто, левый стик, крестовина, A и B работают только в нём.

В меню: частота экрана, разрешение, фовеация и её вид, точка взгляда, показ гравитации, вид поворота, строка частоты внизу и замер скорости. Строка внизу показывает частоту, на которой шлем на самом деле показывает кадры, и зелёная, пока кадры успевают.

## Сборка и установка

```
tools/setup.sh      # инструменты: Godot 4.7.2, шаблоны экспорта, драйвер Adreno для проверок без шлема
tools/export.sh     # сборка для шлема
```

На самом Фрейме `tools/export.sh` кладёт сборку в `~/wormhole-vr/wormhole_vr.arm64` — она уже есть в библиотеке Steam одной записью. В остальных местах получается `godot/build/wormhole_vr_<ветка>_steam_frame.zip`; с компьютера на Windows его ставят в шлем по SSH: вписать имя и адрес Фрейма в `tools/deploy_frame.ps1` и перетащить zip на `tools/deploy_frame.bat`. Логи со шлема — `tools/frame_logs.bat`, скриншоты — `tools/frame_screens.bat`.

## Проверки

Стерео и рендер проверяются без шлема, на программном Vulkan. Godot запускается и с имитацией шлема, и через настоящий OpenXR под Monado. Компилятор шейдеров шлема гоняется без GPU, а цена кадра оценивается эмулятором его системы команд. На самом Фрейме всё это само уходит в контейнер (`tools/box.sh`), чтобы не трогать шлем, в котором сидит человек.

```
tools/test_stereo.sh    # стерео: каждый глаз против Godot, обязательно перед каждой сборкой
tools/test.sh           # тесты Godot: ходьба, меню, руки, физика, гравитация, замер скорости
tools/test_openxr.sh    # приложение через OpenXR под Monado
python3 ref/test_gpu.py # точность шейдера против эталона во float64
```

Подробно, с точностью и инструментами для шейдера, → [docs/checks.md](docs/checks.md).

## Устройство

```
godot/
  main.gd             сцена и зритель: ноги на полу, оси комнаты, голова; ходьба и поворот
  tracer.gd           трассировщик: экранный квад, выбор шейдера, униформы, предметы, трафарет
  shaders/            ядро трассировщика (wormhole_core.gdshaderinc), лучи глаз, варианты шейдера
  wormhole_space.gd   геометрия на CPU: геодезические, перенос осей, гравитация, таблицы для шейдера
  scene.json          неподвижные предметы: одна сцена для шейдера, физики и тестов
  toys.gd, ball_world.gd, hands.gd    мячи и кубы, их физика, руки
  foveation.gd, split_pass.gd        фовеальный рендеринг
  menu.gd, frame_rate.gd, rate_meter.gd, bench.gd    меню, частота кадров, замер скорости
  check_scene.gd      сцена проверки стерео
  tests/              тесты в Godot
ref/                  эталонная математика во float64 и тесты точности
tools/                установка, тесты, сборка, установка на Фрейм, модель цены кадра
docs/                 как всё устроено
```

## Ограничения

- Метод держится на сферической симметрии: тор или произвольный 4D SDF потребуют вести каждый луч численно.
- Освещение своё в каждом мире, теней нет.
